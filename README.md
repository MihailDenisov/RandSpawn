# RandSpawn (черновой проект)

Серверный мод NeoForge 1.21.1 для персональных случайных точек появления игроков.

## Поведение v0.1

- в автоматическом режиме при первом входе создаётся безопасная персональная
  точка и игрок переносится к ней;
- в опциональном режиме первый вход только открывает одноразовое окно получения
  точки (по умолчанию 15 минут реального времени, включая время офлайн), а
  `/randspawn` до истечения срока создаёт точку и телепортирует игрока;
- запись хранит UUID, актуальный ник, измерение и координаты;
- обычный сон и респаун у кровати работают без вмешательства мода;
- если vanilla-точка (кровать/якорь) отсутствует, используется RandSpawn;
- если сохранённая точка стала физически опасной, мод ищет ближайшую безопасную
  позицию вокруг неизменяемого исходного якоря; по умолчанию проверяются
  включительные смещения от -16 до +16 по X/Y/Z;
- если локальное восстановление не удалось, запись не меняется, а текущий
  респаун остаётся на vanilla world spawn;
- данные всех игроков сохраняются глобально в `SavedData` Overworld;
- административная команда: `/randspawn`.

## Требования

- JDK 21;
- VS Code;
- Extension Pack for Java;
- Gradle for Java.

После открытия папки дождитесь импорта Gradle. Удобные задачи доступны через
`Terminal → Run Task`:

- `gradle: build` — тесты и сборка;
- `gradle: test` — только модульные тесты;
- `gradle: runServer` — dev-сервер;
- `gradle: runClient` — dev-клиент.

В терминале используются те же команды:

```bash
./gradlew build
./gradlew runServer
```

На Windows:

```powershell
.\gradlew.bat build
.\gradlew.bat runServer
```

Готовый JAR появляется в `build/libs/`.

## Команды

- `/randspawn` — своя точка или одноразовое получение в опциональном режиме;
- `/randspawn info` — своя точка;
- `/randspawn help` — краткая справка;
- `/randspawn info <ник>` — запись игрока (уровень прав 2);
- `/randspawn tp [ник]` — телепорт администратора (уровень прав 2);
- `/randspawn set [ник]` — назначить текущую позицию (уровень прав 2);
- `/randspawn regenerate [ник]` — найти новую точку (уровень прав 2);
- `/randspawn remove <ник>` — удалить запись (уровень прав 2);
- `/randspawn list` — список записей (уровень прав 2);
- `/randspawn reload` — пояснение о перезагрузке server config (уровень прав 2).

После первого запуска конфиг создаётся в
`world/serverconfig/randspawn-server.toml`.

`assignment.automatic=true` включает прежнее автоматическое назначение. При
`false` первый вход без существующей точки сохраняет одноразовый срок
`assignment.claimWindowMinutes`. Срок хранится как абсолютное системное время и
не приостанавливается, пока игрок офлайн или сервер выключен. Переключение режима
не удаляет существующие точки или уже созданные окна.

Границы локального восстановления задаются шестью включительными параметрами
`localRepair.minOffsetX`/`maxOffsetX`, `minOffsetY`/`maxOffsetY` и
`minOffsetZ`/`maxOffsetZ`. Обратный порядок границ нормализуется.

## Работа с Codex

Проект содержит:

- `AGENTS.md` с архитектурными ограничениями и политикой делегирования;
- `.codex/config.toml` с GPT-5.6 Sol / Medium для основной сессии и лёгким
  GPT-5.6 Luna / Low для рутинных субзадач;
- `.codex/agents/routine-worker.toml` с узким профилем исполнителя;
- `.agents/skills/` с проверкой сборки и паритета локализаций.

Запускайте Codex из корня репозитория, чтобы он увидел project skills и
инструкции. Доступность конкретных моделей зависит от вашей рабочей области;
если указанный ID модели недоступен, измените его в `.codex/config.toml` и
профиле агента, не ослабляя правила из `AGENTS.md`.

## Статус черновика

Это рабочая стартовая реализация, а не production-релиз. Minecraft-aware JUnit
проверяет математику поиска, сериализацию записей и решение о применении
fallback. Перед публикацией всё ещё нужны world-backed GameTests и ручная
проверка на выделенном сервере:

1. первый вход двух игроков и минимальная дистанция в автоматическом режиме;
2. смерть без кровати;
3. смерть с целой кроватью;
4. смерть после разрушения кровати;
5. повторный вход и смена ника;
6. повреждённая/застроенная персональная точка;
7. локальное восстановление выше препятствия и ниже точки без пола;
8. получение точки до/после срока, неудачная повторная попытка и перезапуск
   сервера в опциональном режиме;
9. все административные команды и права OP.

Подробные границы реализации описаны в `docs/DESIGN.md`.
